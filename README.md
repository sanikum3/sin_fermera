# Семинар «Срезы»: задача и правила

Задача — спрос новых ПВЗ: по точке предсказать квантили среднедневного числа заказов
`p10 / p50 / p90`. Условие, признаки, формат посылки и метрика **Operational Score** (0–100,
больше лучше: 40 % качество квантилей P + 60 % прибыль портфеля открытий B) — в `data/README.md`.
Данные — `data/train.csv`, `data/test.csv`, `data/sample_submission.csv`. **Точки теста новые**: соседние точки похожи друг на друга, и случайные фолды
это не учитывают.

## Как начать

1. На странице шаблона нажмите **Use this template → Create a new repository**: публичный, ветка `main`.
2. Ссылку на свой репозиторий — в лист «Участники» таблицы семинара.
3. Клонируйте: данные уже в `data/`. `solution.ipynb` — заготовка с константным прогнозом, она уже пишет `submission.csv` и `cv.json`; замените прогноз и разбиение на свои.
4. Коммитьте и пушьте в `main`: срезы забирают именно его.

## Что лежит в репозитории к каждому срезу

| Файл | Что это |
|---|---|
| `solution.ipynb` | чистовик: выполняется сверху вниз, читает `data/…`, пишет `submission.csv` и `cv.json` и **печатает `cv.json` последней ячейкой** (`print(json.dumps(cv))`) |
| `submission.csv` | ваш ответ: `id, predicted_daily_orders_p10, predicted_daily_orders_p50, predicted_daily_orders_p90`, строки как в `sample_submission.csv`, 0 ≤ p10 ≤ p50 ≤ p90 ≤ 5000 |
| `cv.json` | ваша оценка: `{"name": "lgb_geo", "metric": "quantile_quality_x100", "folds": [71.2, 68.9, 70.4, 69.7], "cv": 70.05, "std": 0.83}` |
| `lab.ipynb` (по желанию) | черновик, не прогоняется |

**Что заявлять в `cv.json`.** Полный Operational Score на train не посчитать — затраты и сценарии
скрыты. Считается его открытая часть: качество квантилей **100·P** на ваших OOF-предсказаниях
(формула P — в условии, готовая функция — `data/metric_cv.py`):

```python
import sys; sys.path.insert(0, "data")
from metric_cv import quantile_quality, cv_json
folds = [100 * quantile_quality(y[val], oof[val, 0], oof[val, 1], oof[val, 2], city[val]) for val in val_indices]
cv = cv_json("lgb_geo", [f / 100 for f in folds])     # пишет cv.json и возвращает словарь
print(json.dumps(cv))
```

Раз в 10 минут скрипт берёт `main` каждого репозитория: `submission.csv` считается на публичной
части и попадает на табло; `solution.ipynb` прогоняется у нас сверху вниз в чистом окружении без
сети. Тот же коммит, что в прошлый срез, — ничего не пересчитывается. Срезы: 20, 30, 40, 50, 60 и
70-я минута; последний — финальный.

## Окружение прогона

Python 3.11.16, пакеты — `requirements.lock` (pip freeze образа: lightgbm 4.6, xgboost 3.2,
catboost 1.2.10, sklearn 1.9), без сети, 2 CPU, 4 ГБ, лимит 3 минуты на ноутбук. Данные лежат в
`data/` рядом с ноутбуком, туда же положен `metric_cv.py`. Проверить своё окружение:
`python check_env.py`. Воспроизвести его: `python3.11 -m venv .venv && . .venv/bin/activate &&
pip install -r requirements.lock`. Перед пушем: сохранить → Restart & Run All → сохранить.

## Что видно во время семинара и что считается в конце

Во время семинара на табло только public последнего среза и «файл принят / не принят».
В конце открывается журнал прогонов и итог:

`Итог = Private · R + B − A − C − D`

- **Private** — Operational Score на приватной части того, что ваш ноутбук сделал у нас в финальном срезе.
- **R** — 0.5, если финальный ноутбук упал, не уложился в 3 минуты или не воспроизвёл свои же
  `submission.csv` и `cv.json`; иначе 1.
- **A** — завышенный CV: ваш `cv` (среднее 100·P по фолдам) против 100·P на приватной части вашей же
  посылки, сверх допуска `2·std` (не меньше 5 и не больше 10 баллов); потолок 30. Занижение не штрафуется.
- **B** — +5, если на первом срезе (20-я минута) уже была принятая посылка.
- **C** — −3 за каждый срез, где ноутбук упал или не уложился в лимит (не больше −15).
- **D** — −5, если финальный прогон дольше 120 секунд.

Инструменты любые. Копировать чужой репозиторий бессмысленно: история коммитов открыта.
